## Technical decisions (made by Claude)
- **One endpoint**, `functions/api/sync.js`: `POST` sends local changes + `since` cursor, returns server changes after the cursor, new cursor and counts. `{ping:true}` (or `GET` with the header) = connection test + counts. `OPTIONS` answers a preflight if one is ever sent.
- **Auth**: the app sends the code inside a `text/plain` JSON body (a "simple" request → no CORS preflight, one round trip). `Authorization: Bearer <code>` is also accepted (curl, `GET`). Compared to secret `SYNC_CODE` via SHA-256 digests and constant-time compare. Wrong/missing code → `401`, no data. Missing secret → `500`.
- **Storage**: one table `records(kind, id, data, deleted, updated_at, seq)`; `seq` is a server-side change counter used as the client cursor.
- **Stable IDs**: entries keep `subId|date` (date is the ISO timestamp, unique per entry, identical on devices that imported the same file → no duplicates). Sessions keep `s_…`. Days use the date. Custom exercises / subs use their generated ids. Routine and weekly list are single documents.
- **Clean max never drops**: when two versions of the same max measurement meet, `clean` and `hard` take the higher value regardless of which version wins.
- **No silent loss**: entries and sessions are tombstoned only by an explicit delete. If they vanish locally any other way (e.g. "replace" import), the next "sync now" (full pull) brings them back.
- **D1 query budget**: each request uses a constant handful of queries (bulk read/upsert through `json_each`), so it stays under the free-plan per-invocation limit.
- **Server timestamps**: client `updatedAt` is clamped to server time to stop a wrong device clock from winning forever.
- **Tests**: the real function runs against Node's built-in `node:sqlite` behind a tiny D1-shaped adapter. No new packages, no `wrangler` install.
